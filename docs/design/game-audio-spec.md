# 对局声音与音乐规格

状态：Draft for implementation

原则：音频是状态反馈的补充，不是规则信息的唯一载体。

## 1. 音频总线

```text
Master
├── UI：按钮、开关、面板
├── Game：走子、吃子、非法、将军、结果
└── Music：菜单音乐、对局环境音乐
```

- 默认：总音量 100%，游戏音效 80%，UI 音效 50%，音乐关闭。
- 用户开启音乐后默认 25%，并独立记忆音乐与音效开关。
- 系统静音与平台音频策略优先；应用不得抢占通话、导航或其他主要音频。
- 设置入口提供“音效”“音乐”“触觉”三个独立开关，不使用一个含义不清的总开关。

## 2. Cue 触发矩阵

| Cue | 触发时机 | 当前资源 | 优先级 | 可打断 |
| --- | --- | --- | ---: | --- |
| `uiTap` | 有效命令触下 | `click.wav` | 10 | 是 |
| `newGame` | 新棋局进入玩家回合 | `newgame.wav` | 30 | 是 |
| `moveRed` | 红方普通落子 | `move.wav` | 40 | 是 |
| `moveBlack` | 黑方普通落子 | `move2.wav` | 40 | 是 |
| `captureRed` | 红方完成吃子 | `capture.wav` | 60 | 是 |
| `captureBlack` | 黑方完成吃子 | `capture2.wav` | 60 | 是 |
| `illegal` | 非法走子判定 | `illegal.wav` | 50 | 是 |
| `checkRed` | 红方走法造成将军 | `check.wav` | 80 | 否 |
| `checkBlack` | 黑方走法造成将军 | `check2.wav` | 80 | 否 |
| `draw` | 和棋结果确认 | `draw.wav` | 90 | 否 |
| `win` | 玩家或红方获胜 | `win.wav` | 100 | 否 |
| `loss` | 玩家或黑方获胜 | `loss.wav` | 100 | 否 |

同一步同时满足走子、吃子、将军或将死时，只播放最高优先级 Cue。结果音覆盖将军，
将军覆盖吃子，吃子覆盖普通走子。

## 3. 播放时序

- UI 点击音在确认命令有效后播放，禁用按钮和空白点击不发声。
- 普通走子与吃子音在棋子到达目标交点时播放，不在手指抬起时提前播放。
- 非法音在棋子到达最大偏移处播放，与触觉反馈同步。
- 将军提示在落子音之后 60-100ms 进入；若采用单一高优先级 Cue，则不叠加落子音。
- 结果音在结果已写入棋局状态后播放，面板延后约 250ms 进入。
- 悔棋使用反向移动表现但不倒放原音效；首版使用低音量 `move`，后续补专用 Cue。

## 4. 混音与防叠音

- 同类短音效最多保留一个实例；80ms 内重复触发视为同一次操作。
- 游戏 Cue 到来时，音乐在 80ms 内降低 6dB，并在 Cue 结束后 300ms 恢复。
- `check` 和结果 Cue 播放期间停止较低优先级的 `move`、`capture` 和 UI Cue。
- 切换主题不得更改 Cue 语义；主题可提供同名音色包，缺失时回退默认声音。
- 所有音效应先预加载；首次落子不得因为解码产生明显延迟。

## 5. 音乐方向

当前仓库没有音乐资源。首个音乐包建议包含：

- `menu`: 60-90 秒无明显鼓点的循环段，用于首页和设置。
- `gameCalm`: 90-150 秒低密度循环段，用于普通对局。
- `gameTense`: 可选的同调性层，在残局或计时压力下淡入，而不是切换整首曲目。

音乐需要满足：

- 无人声、无版权风险、循环点无爆音。
- 不用锣鼓或高频打击持续制造紧张感。
- 菜单到对局使用 600ms 交叉淡化；进入后台立即暂停，返回后 400ms 渐入。
- 局势层变化只允许在乐句边界或至少 1 秒淡化内发生。

## 6. 资源技术要求

现有 WAV 为 11kHz 单声道、8/16-bit，适合原型但不建议直接作为最终发行资源。正式资源建议：

- 源文件保留 48kHz / 24-bit WAV，仓库运行资源使用平台验证后的压缩格式。
- 峰值不超过 -1dBFS，短音效响度在同一组内听感一致。
- 头尾裁去无意义静音，并添加极短淡入淡出防止 click/pop。
- 文件名使用语义 Cue，不绑定某个页面或 Widget。
- 音乐和第三方声音必须记录作者、许可证、来源和修改说明。
- 当前 `newgame.wav` 约 5.5 秒，首步落子或终局 Cue 到来时必须停止，不能叠加播放。

## 7. 触觉配合

| 场景 | 触觉 | 声音关闭时 |
| --- | --- | --- |
| 选子 | 轻触，可关闭 | 保留视觉选中 |
| 合法落子 | 轻触 | 保留落点标记 |
| 吃子 | 中触 | 保留目标消失与状态文字 |
| 非法 | 双短触 | 保留往返动画与原因语义 |
| 将军 | 单次强调 | 保留状态行和读屏播报 |
| 结果 | 成功/警告型一次 | 保留结果面板 |

桌面端不模拟触觉；不得用连续触觉伴随棋子移动。

## 8. 生命周期

- `inactive/paused/detached`：暂停音乐，停止未开始的延迟 Cue，释放不必要的流。
- `resumed`：只恢复用户此前允许的音乐，不补播走子或结果声音。
- 耳机拔出或音频焦点丢失：立即暂停音乐，不自动切到扬声器继续播放。
- 设置改变实时生效；关闭音效后应停止当前可打断 Cue。
- 页面销毁时取消订阅，禁止旧棋局继续触发音频。

## 9. 实现建议

- 定义 `GameAudioCue` 枚举与 `GameAudioEvent(id, cue, side, timestamp)`。
- `GamePresentationCoordinator` 按优先级把一个规则结果归并成一个音频事件。
- `GameAudioController` 负责预加载、去重、总线音量、ducking 和生命周期。
- 首选支持 Android/iOS/macOS 且具备低延迟短音效与多总线控制的成熟 Flutter 音频库；
  在落地任务中先做最小原型并测量首播延迟，再确定依赖。
- 用户设置通过本地仓库存储，音频服务不直接访问 UI 状态。

## 10. 验收

1. 冷启动后的第一次走子音延迟不可感知，后续播放无逐步变慢。
2. 同一步只播放一个最高优先级 Cue。
3. 快速选子、非法操作和连续悔棋不会形成叠音或音量峰值。
4. 音乐、音效、触觉三个设置分别持久化并立即生效。
5. 锁屏、来电、耳机拔出、窗口失焦与恢复符合生命周期规格。
6. 关闭全部声音后，所有关键状态仍有完整视觉和语义反馈。
7. Android、iOS、macOS 的听感音量接近，不出现削波、爆音或循环断点。
